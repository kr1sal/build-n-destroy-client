# Client (Godot)

Клиентская часть **Build N Destroy** — многопользовательского FPS в духе Block N Load с разрушаемым блочным миром и крафтом.

Общий обзор проекта, протокол и план по версиям — в корневом [README.md](../README.md).

> **Язык netcode: C#.** Сетевой слой, prediction, reconciliation и interpolation на клиенте пишутся на C# (Godot Mono). GDScript допустим для сцен, UI и чисто презентационного кода, но вся netcode-логика — C#.

---

## 1. Роль клиента

Клиент — **не источник истины**. Он:

- собирает ввод игрока и шлёт серверу `PlayerInput` (намерения, не состояние);
- получает от сервера authoritative snapshots и events;
- рендерит мир, игроков, оружие, блоки;
- выполняет **client-side prediction** для локального игрока и **interpolation** для remote-игроков;
- показывает оптимистичный build/break с откатом, если сервер отверг действие.

Сервер считает движение, физику, оружие, урон, HP, блоки и правила. Клиент этого не дублирует и не оспаривает.

---

## 2. Архитектурные принципы (клиентская сторона)

- **LocalPlayer и RemotePlayer — разные сущности.** Local идёт через prediction + reconciliation, Remote — через interpolation между snapshots.
- **Fixed timestep на сервере** (симуляция 60 Hz, снапшоты 20 Hz). Клиент подстраивается: буферизирует снапшоты, рендерит remote-игроков с небольшой задержкой для плавности.
- **Input sequence numbers.** Каждый отправленный input пронумерован; при получении `last_processed_input` клиент выкидывает подтверждённые inputs и переигрывает оставшиеся поверх authoritative state (reconciliation).
- **Разрушение/постройка блоков** — только по подтверждению сервера. Клиент может показывать оптимистично, но обязан откатывать при rejection.
- **События отдельно от state.** Выстрелы, попадания, смерти, звуки, эффекты — приходят отдельным потоком и триггерят презентационную логику. Клиент не «догадывается» о попадании сам.
- **Транспорт абстрагирован.** Сначала WebSocket/TCP, позже UDP. Gameplay-код не должен знать деталей транспорта.

## 3. Структура (планируемая)

```
client/
├── Network/        // Connection, Protocol, NetworkClient (C#)
├── Gameplay/       // LocalPlayer, RemotePlayer, Weapon, Camera, BlockWorld
├── Prediction/     // InputBuffer, Reconciliation (C#)
└── Interpolation/  // SnapshotBuffer (C#)
```

Netcode-модули (`Network/`, `Prediction/`, `Interpolation/`) — C#. `Gameplay/` — смешанный: игровая логика и интеграция с netcode на C#, презентационные сцены и UI могут быть на GDScript.

---

## 4. План по версиям (клиентский срез)

Клиент на каждом шаге — **минимальный**, ровно столько, сколько нужно, чтобы проверить соответствующий серверный milestone. Подробный план — в корневом README.

- **v0.1** — подключение, отправка WASD + мышь, рендер своей позиции по snapshot.
- **v0.2** — LocalPlayer / RemotePlayer, interpolation для remote, обработка join/leave/spawn.
- **v0.3** — приём shot/hit/death events, muzzle flash, hitmarker, kill feed (ничего локально не «угадываем»).
- **v0.4** — InputBuffer с sequence numbers, prediction движения local-игрока, reconciliation.
- **v0.5** — приём чанка блоков на join и дельт при изменениях; оптимистичный build/break с откатом.
- **v0.6** — выбор героя, разные параметры движения/оружия/блоков, team UI.
- **v0.7** — ничего особенного на клиенте (lag compensation — чисто серверная тема).
- **v0.8** — миграция транспорта на UDP, разделение reliable/unreliable каналов.
- **v0.9** — оптимизации рендера и пропускной способности при 20–40 игроках.
- **v1.0** — lobby, выбор героя и карты, матчмейкинг.

---

## 5. Протокол клиент/сервер

Схема сообщений (`PlayerInput`, `Snapshot`, события) — **контракт**. Клиент не меняет протокол в одностороннем порядке: сначала согласование с серверной стороной. См. корневой README, раздел 2.1 и далее.
