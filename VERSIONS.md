# Client — План по версиям

Клиентский срез плана из корневого [README.md](../README.md), раздел 5. На каждом milestone клиент — **минимальный**, ровно столько, сколько нужно, чтобы проверить соответствующий серверный шаг.

> **Netcode на C#** (Godot Mono). Весь сетевой/prediction/interpolation код — C#. GDScript — для сцен, UI, презентационной логики.

---

## v0.1 — MVP клиент

Цель: убедиться, что один игрок бегает, сервер — источник истины.

- [ ] Godot-проект с C# support (Mono).
- [ ] `Network/Connection.cs` — WebSocket/TCP коннект к серверу, обработка reconnect/disconnect.
- [ ] `Network/Protocol.cs` — сериализация/десериализация gRPC-сообщений.
- [ ] `Network/NetworkClient.cs` — отправка `PlayerInput`, приём `Snapshot`.
- [ ] Сбор ввода: WASD + мышь (yaw/pitch), флаги Jump/Fire/Build/Break.
- [ ] Отправка `PlayerInput` каждый клиентский tick.
- [ ] Приём snapshot → телепорт собственной капсулы в authoritative-позицию (без prediction, без интерполяции).
- [ ] Минимальная сцена: плоскость + skybox + капсула локального игрока + FPS-камера.

**Выход:** игрок видит, как его капсула «телепортируется» по authoritative-позициям. Dejitter пока нет, рывки — ожидаемы.

## v0.2 — LocalPlayer / RemotePlayer, interpolation

Цель: несколько игроков в одной комнате выглядят плавно.

- [ ] Разделение `Gameplay/LocalPlayer.cs` и `Gameplay/RemotePlayer.cs` — разные сущности.
- [ ] Менеджер игроков: спаун/десенд по событиям join / leave / spawn.
- [ ] `Interpolation/SnapshotBuffer.cs` — буфер последних N snapshot'ов.
- [ ] Рендер remote-игроков с задержкой (~100 ms) и линейной интерполяцией позиции/поворота между двумя ближайшими snapshot'ами.
- [ ] Простой «игрок»-меш (капсула + стрелка направления).
- [ ] UI-список подключённых игроков.

**Выход:** 2–4 капсулы бегают плавно, не телепортируются.

---

## v0.3 — Стрельба, урон, смерть (презентация)

Цель: клиент показывает выстрелы/попадания/смерти **по событиям от сервера**, ничего не угадывает локально.

- [ ] Приём event-потока: `shot_fired`, `hit`, `death`, `respawn`.
- [ ] Muzzle flash + звук выстрела — только по событию `shot_fired`.
- [ ] Hitmarker + звук попадания — только по событию `hit`.
- [ ] Kill feed — по событию `death`.
- [ ] HP-бар локального игрока — из snapshot.
- [ ] Ammo-счётчик — из snapshot.
- [ ] Экран смерти + респаун-таймер.

**Важно:** никакого «локального» определения попадания. Клиент не стреляет raycast'ом — только отображает то, что прислал сервер.

**Выход:** можно отстреливать друг друга; все эффекты — реакция на серверные события.

## v0.4 — Prediction + reconciliation

Цель: локальный игрок реагирует мгновенно, но остаётся в синхроне с сервером.

- [ ] `Prediction/InputBuffer.cs` — очередь неподтверждённых `PlayerInput` с sequence numbers.
- [ ] Отправка input'ов с sequence; хранение их локально.
- [ ] Локальная симуляция движения LocalPlayer (повтор серверной формулы: та же gravity, speed, friction).
- [ ] Приём snapshot с `last_processed_input` → откат LocalPlayer в authoritative-позицию → переигрывание неподтверждённых inputs поверх неё.
- [ ] Сглаживание расхождений (если расхождение малое — визуальный blend, если большое — snap).

**Выход:** управление отзывчивое, рассинхрон не копится, после лаг-спайка игрока «мягко» возвращает на правильную позицию.

## v0.5 — Блочный мир

Цель: клиент рендерит воксельную карту и показывает build/break с оптимистичным откатом.

- [ ] `Gameplay/BlockWorld.cs` — приём чанка блоков на join (полная карта или первая зона).
- [ ] Меш-билдер для чанков: greedy meshing или простой куб-пер-блок на старте.
- [ ] Приём snapshot-дельт блоков: `block_changed(x, y, z, type, hp)`.
- [ ] Reticle подсвечивает прицеленный блок (raycast по локальной копии карты).
- [ ] Нажатие Build/Break:
  - локально проигрываем изменение (оптимистично);
  - шлём `PlayerInput` с флагом;
  - если сервер в следующем snapshot не подтвердил — **откатываем**.
- [ ] UI: тип выбранного блока, доступное количество материала.

**Выход:** можно пробивать стены и строить укрытия; при rejection от сервера блок возвращается на место.

## v0.6 — Герои и команды

Цель: team-игра с выбором героя при респауне.

- [ ] Экран выбора героя (3–4 архетипа): параметры из конфига с сервера или общего манифеста.
- [ ] Разные параметры LocalPlayer в зависимости от героя: скорость, оружие, стоимость/прочность ставимых блоков, одна активная способность.
- [ ] Hotkey для активной способности.
- [ ] Team UI: цвет команды, иконки союзников/врагов, индикатор точки/ядра.
- [ ] HUD режима: таймер, счёт точек, список живых.

**Выход:** 2v2 / 4v4 раунд с удержанием точки.

## v0.7 — Lag compensation (клиентская сторона почти пустая)

Основная работа — на сервере. Клиент только:

- [ ] Шлёт точный `client_time` / sequence вместе с input'ом, чтобы сервер мог откатить состояние на момент выстрела.
- [ ] Возможно, корректирует hitmarker-feedback, если сервер начнёт присылать более подробные hit-события.

## v0.8 — UDP transport

Цель: перевести realtime-трафик на UDP, оставить TCP для control-плоскости.

- [ ] `Network/UdpTransport.cs` — UDP-сокет (ENet / Godot Multiplayer / raw).
- [ ] Sequence numbers + ack-битовая маска для selective reliability.
- [ ] Два канала: unreliable (snapshots, inputs) и reliable (события, state на join).
- [ ] TCP/WebSocket остаётся для auth, lobby, chat.
- [ ] Декодирование delta snapshots.
- [ ] Обработка потерь: при пропуске snapshot — продолжать интерполировать по следующему.

**Выход:** gameplay-трафик по UDP, latency ниже, control-плоскость всё ещё по TCP.

## v0.9 — Масштаб и качество рендера

Цель: 20–40 игроков в комнате без просадок.

- [ ] Interest management на клиентской стороне: отрисовывать/обновлять только видимых/близких игроков.
- [ ] LOD для мешей блоков и игроков.
- [ ] Culling чанков блоков.
- [ ] Профилировка: GPU/CPU time, bandwidth, GC pauses.
- [ ] Опционально: пулы объектов для частиц/эффектов.
